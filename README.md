# 米游社壁纸下载器 v3.1

> 一键批量下载米游社用户发布的高清壁纸
>
> **纯 Python 标准库实现，零第三方依赖，装好 Python 直接跑。**

---

## 功能特点

- 🔍 **并行扫描** — 利用帖子 ID 游标语义多起点并发抓取，扫描提速约 3.6 倍
- 🎨 **批量下载** — 自动筛出壁纸帖，一键下载全部图片
- 🖼️ **高清原图** — 下载用户上传的原始大图（单张几 MB 到十几 MB）
- ⚡ **多线程并发下载** — 默认 8 线程，界面最高可拉到 512（见下方实测）
- 🧵 **线程级实时视图** — 扫描和下载的**每一个线程**都有自己的状态卡片：
  当前任务、进度百分比、单线程速度、已完成数量
- 🔄 **可靠断点续传** — 先写 `.part` 临时文件、成功后再原子改名，
  半截文件不会被误判成"已下载"
- 📅 **日期范围筛选** — 指定起止日期（含首尾两天）
- 📝 **三种命名** — 日期+标题 / 日期+ID / 仅帖子 ID
- ⏹️ **随时停止** — 停止后自动清理临时文件
- 📊 **实时进度** — 总进度 + 帖子/图片双进度条 + 速度 / 已用时 / 预计剩余
- 📜 **彩色日志** — 增量推送，长时间下载也不拖慢界面
- 🚀 **零依赖** — 只用 Python 标准库

## 使用说明

### 第一步：获取帖子列表（并行扫描）

1. 填米游社用户 ID（纯数字）
2. 点"获取帖子"
3. 界面会实时显示**每个探测线程**正在抓哪个 ID 区段、已发现多少帖子

> **用户 ID 怎么找？**
> 打开米游社用户主页，URL 中 `id=` 后面的数字。
> 例：`https://www.miyoushe.com/ys/accountCenter/postList?id=11316600` → `11316600`

### 第二步：设置参数

| 设置项 | 说明 |
|--------|------|
| 保存到 | 相对路径以程序目录为基准，留空用 `wallpapers/` |
| 时间范围 | 全部壁纸 / 指定日期段（含首尾两天） |
| 文件命名 | 日期+标题 / 日期+ID / 仅帖子 ID |
| 并发线程 | 1~512，对数滑杆 + 快捷档位；扫描与下载共用 |

### 第三步：开始下载

点"开始下载"，面板会列出每个线程的当前文件、进度条、实时速度和完成计数。
可随时停止。

## 关于扫描并行化

接口 `userPostList` 的分页游标是 `offset=<帖子 ID>`，语义经实测确认：

```
GET .../userPostList?uid=U&size=20&offset=X
  → 返回该用户 post_id < X 的最新 20 条（降序）
  → X 可以是任意帖子 ID，不必须是上一页返回的 next_offset
```

`size` 有 20 的硬上限，传更大也会被忽略。所以顺序扫描必须翻 49 页。

关键在于**端点判据**：设同一用户的帖子序列 p₁ > p₂ > … > p_N，
窗口 A = [pᵢ … p_{i+19}]，窗口 B = [pⱼ … p_{j+19}]，A 在 B 上方。
因为窗口都是序列上的连续区间，两窗口之间**存在漏帖**当且仅当：

```
j > i+19   ⟺   A.lo > B.hi
```

所以只要让所有相邻窗口都满足 `A.lo <= B.hi`，覆盖就必然完整——
这是个**充要条件**，可以直接自检，不是启发式猜测。

实现方式：先沿 ID 轴几何撒 16 个起点并行抓取，再找出所有
`A.lo > B.hi` 的缺口，对每个缺口并行地在内部插点细分 + 沿前沿下潜，
反复迭代直到没有缺口。

### 实测（同一账号，961 条帖子，两次交替测量）

| | 帖子 | 请求数 | 平均延迟 | 墙钟 |
|:--|---:|---:|---:|---:|
| 顺序扫描 | 961 | 49 | 0.259s | 15.43s |
| **并行扫描（16）** | 961 | **148** | 0.265s | **4.23s** |
| 顺序扫描 | 961 | 49 | 0.250s | 14.98s |
| **并行扫描（16）** | 961 | **148** | 0.259s | **4.15s** |

- **提速约 3.6 倍**
- 平均单次请求延迟两者完全一致（0.26s），说明快的是真并行，不是单请求变快
- **代价：请求数约 3 倍**（148 vs 49，多出来的是缺口细分探测）。
  这是刻意选的速度优先取舍，有 `MAX_PROBES=600` 硬上限兜底

### 正确性验证

把并行扫描和顺序扫描的结果逐帖比对 ID 集合：

```
并行独有: 0    顺序独有(漏帖): 0    集合完全一致: True
```

两次独立测量均通过。顺序扫描作为基准真值，结果 961 条帖子、
807 个壁纸帖、16236 张图片，与并行扫描完全一致。

## 关于下载并发（实测数据）

同一帖子池、同样 12 秒窗口，只改线程数：

| 并发线程 | 12 秒下载量 | 实测吞吐 |
|---------:|------------:|---------:|
| **8** | **690.9 MB** | **56.5 MB/s** |
| 32 | 271.8 MB | 22.5 MB/s |
| 64 | 123.0 MB | 10.2 MB/s |
| 128 | 123.7 MB | 10.3 MB/s |
| 256 | 0 MB | 12 秒内一张都没完成 |
| 512 | 0 MB | 12 秒内一张都没完成 |

冷却 20 秒后打乱顺序复测，结论稳定（8 线程 36.5 / 29.2 MB/s，
32 线程 17.7 MB/s）。全程 CPU 只占 1.2~1.6 核，瓶颈不在本机也不在代码，
而是**图站按来源 IP 对并发连接限速**。

**结论：下载阶段线程越多越慢。** 所以默认 8，界面上按档位实时提示
"✅ 推荐 / ⚠️ 会变慢 / 🐌 明显更慢"，上限 512 保留但别轻易用。

> 注意：扫描快 ≠ 下载快。扫描是对 API 发小请求（每页 20 条 JSON），
> 16 路并发没问题；下载是从图床拉几 MB 的大图，图床对并发连接敏感得多。
> 两者用同一个滑杆，但最优值完全不同。

## API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/fetch` | POST | 并行扫描帖子列表（可带 `threads`） |
| `/api/download` | POST | 开始下载 |
| `/api/stop` | POST | 停止当前任务 |
| `/api/open_folder` | POST | 在系统文件管理器中打开下载目录 |
| `/api/status?after=N&wv=M` | GET | 增量状态：`after` 取新增日志，`wv` 取线程快照 |
| `/api/config` | GET | 版本、默认目录、线程上限 |

**扫描：**

```json
POST /api/fetch
{ "uid": "11316600", "threads": 16 }
```

**下载：**

```json
POST /api/download
{
  "save_dir": "wallpapers",
  "date_mode": "range",
  "start_date": "2026-01-01",
  "end_date": "2026-12-31",
  "naming_mode": "date_title",
  "threads": 8
}
```

`/api/status` 只在 `workers_version` 变化时回传 `workers` 数组，
数组每项形如：

```json
{ "id": 3, "phase": "download", "active": true,
  "detail": "2026-09-23_09.png", "cur": 4194304, "total": 7340032,
  "speed": 5242880.0, "done": 7, "failed": 0 }
```

## 技术架构

- **后端**：Python 标准库 `http.server`（`ThreadingHTTPServer`）+ `urllib`
- **前端**：纯 HTML + CSS + JavaScript，无框架、无构建步骤
- **扫描**：多起点并行探测 + 端点判据填缝，`MAX_SCAN_THREADS=16`
- **下载**：`queue.Queue` 任务队列 + 常驻守护线程，按任务量自动收敛
- **完整性**：`.part` 临时文件 + `os.replace` 原子改名
- **可观测**：统一线程槽位，扫描/下载共用；日志按 `seq` 游标增量拉取
